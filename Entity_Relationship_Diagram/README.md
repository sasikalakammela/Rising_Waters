# Entity Relationship Diagram (ERD)

## Project Title
Flood Prediction Analysis System

## Overview
This Entity Relationship Diagram (ERD) represents the database design of the Flood Prediction Analysis System. It defines the main entities involved in the application, their attributes, primary keys, foreign keys, and the relationships between them. The ERD serves as the foundation for designing the database and maintaining data integrity.

## Objective
The objective of this ER diagram is to provide a structured representation of the database that stores user information, weather data, machine learning model details, and flood prediction results.

## Entities

### 1. Users
Stores the details of users who access the system.

**Attributes:**
- UserID (Primary Key)
- Name
- Email
- Password
- Role

### 2. Weather_Data
Stores weather-related information used for flood prediction.

**Attributes:**
- DataID (Primary Key)
- UserID (Foreign Key)
- AnnualRainfall
- CloudVisibility
- Temperature
- Humidity
- SeasonalRainfall

### 3. ML_Model
Stores information about the trained machine learning model.

**Attributes:**
- ModelID (Primary Key)
- ModelName
- AlgorithmType
- Accuracy
- ModelFile

### 4. Prediction_Result
Stores the prediction generated by the machine learning model.

**Attributes:**
- PredictionID (Primary Key)
- DataID (Foreign Key)
- ModelID (Foreign Key)
- FloodResult
- FloodProbability
- PredictionDate

## Relationships

- One User can have multiple Weather_Data records (One-to-Many).
- Each Weather_Data record generates one Prediction_Result (One-to-One).
- One ML_Model can generate multiple Prediction_Result records (One-to-Many).
